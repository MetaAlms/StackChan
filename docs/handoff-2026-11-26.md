## 2. 已完成并验收

用户 2026-11-04 亲自验收："响度够，破音/电流声基本没有"。

最后一轮成功样本（`m1-a1`）：

```
RUNNING 22.1 s → 播放 30 s → state=Done
VOLUME 100（effective=100）
write_ok=740  write_failed=0
submitted=648240 样本（≈27 s）  max_abs=15603（不削波）
```

关键修复链路（按发现顺序，详见 findings B68–B72）：

1. **Wi-Fi 省电是下行卡顿主因**（B69）：M15 从未请求 `PERFORMANCE`，整轮跑在
   `WIFI_PS_MIN_MODEM`，导致 `rx_full` 丢包、`decoded` 腰斩。关闭后 `rx_full=0`。
2. **AEC 与媒体循环争 core1**（B68/B69）：AEC 单块 13.2 ms / 16 ms（82% 一个核），
   无法与媒体循环共存 —— 二选一的调度都没赢，见"未解决"。
3. **I2C 只重试、不复位总线**（B70/B72）：`i2c_master_bus_reset()` 会让 PMIC/FT6336
   句柄失效并 abort，已删除；改为对 `esp_codec_dev_open` 重试 3 次。
4. **RUNNING 必须等数据通道真开**（B71）：否则没连上也报 Running、`sent=0`、`elapsed` 为负。
5. **重试放在命令层**（B71/B72）：固件内 `Transport::Reset()` 会触发 `on_before_close`
   拆掉音频链路，第二次虽握手成功但永远不 RUNNING。
6. **音量**（B72）：新增 `VOLUME <0..100>` 控制台命令 + `PushWebRtcPcm` 内 2× 增益（带钳位）。

## 4. 未解决问题（按优先级）

### P0 上行 AEC 欠载 —— 设备"听不清"

- 现象：`AFE feed avg ≈ 25 ms / 16 ms 块`、`dropped_samples ≈ 39 万`（30 s 跑丢约 16 s 音频）。
- 已排除：降噪不是瓶颈（NSNet → WebRTC NS 后 `avg` 仍 13.2 ms）；PMIC 供电已按官方修正（B65）。
- 现状：把媒体循环固定 core0 可让 AEC 回到 13.2 ms/0 丢样本，但下行会被
  `audio_input`/Wi-Fi 挤死（`rx_full` 飙到 92）；不固定则反过来。
- **两条候选路线**：
  1. **把 Opus 编解码移出媒体循环**（编码 20 ms/帧 + 解码），给 core1 腾出时间；
  2. **真正降低 AEC 单块耗时**：目前只知道 `AFE_MEMORY_ALLOC_MORE_PSRAM`（PSRAM 访问慢）
     和 `AFE_MODE_HIGH_PERF` 两个未试过的旋钮，需实测对比。

### P1 DTLS 握手慢（2–34 s 波动）

- 现象：`CLient handshake fail ret -0x6900`（WANT_READ）刷屏，SDP 已 `http=200`、ICE 已 PAIRED。
- 影响：准备超时 10 s 偶有误判；用户体感"先静音半分钟"。
- 建议：准备超时调到 **15 s**；命令层重试保持（实测新连接 1.9 s 就能通）。

### P2 其他

- 双讲 / 语音打断：完全未验证（依赖 P0）。
- 2× 增益后峰值 15603，还有约 2 倍余量；若继续加需盯 `max_abs` 防削波。
- M2（连续采集、本地 stop、UI/表情、重连）未开始。

## 6. 设备测试 SOP（血泪教训，必须遵守）

1. **一次会话只开一个串口句柄**，所有轮次共用；不要 open/close 反复。
2. **等启动横幅** `IDLE; USB commands: ...` 出现再发命令；启动中发 `START` 会丢。
3. 需要刷机时：**先用同一句柄脉冲 RTS 复位**，让"关串口→esptool 打开"发生在一次全新 boot 之后。
4. 连接失败要**在命令层重发全新 `START`**（不要指望固件内重试）。
5. 命令：`START <id> near|duplex|self <5..180>`、`STOP <id>`、`STATUS`、
   `AUDIT <3..10>`、**`VOLUME <0..100>`**。
6. 日志判读：`RUNNING` 才算真跑；`FINAL ... reason=prepare_timeout` 是没连上；
   `recovering`/`output open failed` 是功放 I2C 抖动。

### 常见故障 → 处置

| 现象 | 原因 | 处置 |
|---|---|---|
| 串口静默但 `ioreg` 仍能看到设备 | USB CDC 一次 boot 只允许一次 host 打开 | 一个句柄跑到底；否则物理重插 |
| 设备从 USB 完全消失 | 物理链路（线/口/供电） | 换线/换口，别经扩展坞 |
| 长时间没声音 | DTLS 握手慢，前面几十秒是静音 | 等 ≥ 15 s；或命令层重发 START |
| `RUNNING` 但 `sent=0` | START 发在启动中，或传输未连上 | 等横幅；已加传输门禁 |
| `ESP_ERROR_CHECK ... I2cDevice::WriteReg` | 有人调过 `i2c_master_bus_reset()` | **禁止**；功放失败只重试 |

## 9. 踩坑清单（不要重犯）

1. 固件内 prepare 重试 → `Transport::Reset()` 触发 `on_before_close`，音频链路被拆，
   第二次握手成功也永远不 RUNNING。
2. `i2c_master_bus_reset()` → 同总线 PMIC/触摸句柄失效 → `ESP_ERROR_CHECK` abort 重启。
3. 反复 open/close 串口 → CDC 永久静默（芯片活着，esptool 也连不上）。
4. 启动中发 `START` → 半条命令，出现"Running 但 sent=0"。
5. 换 WebRTC NS 想降 AEC 开销 → 无效果，AEC 算法本身才是成本。
6. 媒体循环固定 core0 → 下行被挤死；不固定 → 上行被挤掉。**必须从算法/拆分上解决**。
