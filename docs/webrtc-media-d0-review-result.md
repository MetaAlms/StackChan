## D0-1 [P2] Opus 帧长接口返回字节，不能直接当样本

SPEC 第 327 行把 `esp_opus_enc_get_frame_size` 的输入长度称为“帧样本数”。现有 `audio_service.cc:82–83` 调用后明确除以 `sizeof(int16_t)`。48k、mono、s16、20ms 对应 1920 字节／960 样本；重采样器的 `actual_out` 是每声道样本数。按当前文字实现会混用单位。

修改契约：接口取得输入帧字节数和编码输出容量；每声道样本数为 `in_size / (channel * sizeof(int16_t))`，编码 `in_frame.len` 使用字节。PLAN 的 M1 编码任务引用同一契约。

## D0-2 [P1] M1.5 试验依赖的最小媒体能力仍排在 M2

PLAN 第 118–126 行只列下行播放、确认连续采集与 T1–T4；真实麦克风上行、本地停止、在途任务隔离与跨通道边界却在第 148、151–152 行才实现。T3 已要求旧播放实际停止，缺少这些前置会把探针未实现停止误判成目标失败。

将真实麦克风→AFE16k→48k 编码→RTP、最小本地 stop/cancel、在途代际隔离、迟到旧包处理与乱序验证列为 **M1.5 的试验前置**。M2 再接入产品 AudioService/UI。未知的 RTP 与 response_id 关联规则应在执行 T3 前冻结并验证，不必现在伪造规则。SPEC 第 303 行“§4.6 给出替代门控”引用错误：§4.6 只定义转换，改成实际设计位置或明确前置探针任务。

## D0-3 [P2] T4 单独失败未归类，回退决定不一致

SPEC 第 470–472 行、PLAN 第 132–134 行：通过要求 T1–T4 全过，失败只覆盖 T2/T3；T4 单独失败落不到任何结果。补充取消后恢复缺陷的分支，交评审定位；若采集、时间轴或会话本身已失效，先修实验。不得把恢复缺陷直接归因为 AEC。

M1.5 的目标表述应是验证当前裸 esp_peer 路径的可用全双工／打断行为；行为结果不能独立定位回声控制发生于服务端。SPEC 第 573 行无条件回退与 §6.2“交 Codex 评审后决策”矛盾，统一为评审后决定，不以探针失败直接结束已授权移植。

## D0-4 [P2] 干净重建应隔离验证，保留当前生成目录

SPEC 第 209–211 行要求每阶段删除当前 `xiaozhi-esp32/` 与 `managed_components/`。这些目录含未跟踪的开发产物，当前工作环境不能作为破坏性重建试验对象。改为独立临时 checkout／构建目录：受版本控制的源码、patch 与组件锁能重建，`fetch_repos.py` 获取上游源码，ESP-IDF 配置阶段恢复 managed components。不复制或输出凭据，不删除当前依赖、构建产物或本地配置。
